---
title: 员工
description: 新建和管理员工，设置它们的引擎、目录、规则和权限。
---

员工是一个 Agent CLI，有自己的引擎、工作目录、规则和权限。Bee 把活派给员工，多个员工可以同时干活。

## 新建

跟 Bee 说：

> 帮我建一个员工，叫 Maya，负责后端修复，工作目录是 ~/code/api。

或者点对话列表顶部的 **+**。桌面版也可以按 ⌘N 或 Ctrl+N。

| 字段 | 说明 |
| --- | --- |
| 名称 | 必填，不能重复。 |
| AI 引擎 | 必填，默认选中默认引擎。 |
| 描述 | 员工负责什么。Bee 按描述分派任务，建议填写。 |
| 工作约束 | 长期规则，见[工作约束](/zh/docs/constraints/)。 |
| 引擎参数 | 附加的 CLI 参数，例如 `--effort high`。 |
| 工作目录 | 默认 `~/.openbee/worker/<员工 ID>`，不存在时自动创建。 |
| 权限配置 | 见[权限](#权限)。 |

后四项在 **高级配置** 里。

## 派活

- 告诉 Bee 要做什么，Bee 按描述挑员工。
- 以员工名字开头可以跳过 Bee：`Maya 看看登录测试`。名字里不能有空格。
- 在桌面版和 Web 控制台里，每个员工还有自己的对话。

## 状态

头像上的圆点表示 **空闲**、**工作中** 或 **异常**。工作中的员工收到的新任务会排队。异常表示上一次运行失败，例如引擎没有安装。`/list` 可以查看所有员工的状态。

## 编辑

点员工对话顶部的名字，再点 **编辑**。**约束**、**权限** 和 **环境变量** 标签页也在这里。也可以直接跟 Bee 说。

没有单独设置引擎的员工使用默认引擎：在设置的 **默认引擎** 里修改，或发送 `/engine <引擎>`。切换引擎后会从新对话开始。

## 权限

员工随时可以给你发消息。想让它在工作时读取 OpenBee 的数据，需要授予：

| 权限 | 可读取 |
| --- | --- |
| 查询员工 | 员工及其状态 |
| 查询任务 | 任务及其执行记录 |
| 查询消息 | 消息记录 |

新员工默认没有权限。只有 Bee 能新建或修改员工和任务。

## 环境变量

每次运行都会传给引擎。**全局变量** 和 **Bee 变量** 在设置 → **环境变量** 里设置，员工级变量在员工的 **环境变量** 标签页里设置。同名时以员工级为准。

## 删除

打开员工资料，选择 **删除员工**，输入名字确认。勾选 **同时删除工作目录** 会一起删掉它的目录。它的私聊记录也会被删除。
